## Implementation Contract

The user tested the gap tool (TASK-SKRIPT-40-04-09) on staging on 2026-10-19 and asked for three things (U1-U3). The user answered the lead's questions Q1-Q8 on 2026-10-19 and accepted the plan. Status `ready` by `agent-planning:user-closure-gate` (user answers 2026-10-19, relayed by orchestrator 944b5a5a).

Behaviour:

01. With the gap tool on, a click on a gap reverts it in one undo step. A Lucktext gap becomes its first accepted answer as plain text; a dropdown gap becomes its correct option's text (Q1).
02. The reverted word keeps the rest of the gap hidden: its other accepted answers, automatic values and excluded values, or its other dropdown options. The link is attached to the word's text, so it moves with the word when the text around it changes, and deleting the whole word deletes it (Q2 i). Copy and paste never copies the link.
03. With the tool on, a click on a word that has kept answers makes the whole gap again in one undo step. The word's current text becomes the first answer (Lucktext) or the correct option's text (dropdown), and the kept answers and options come back, so an unedited word restores the gap exactly (Q2 ii).
04. With the tool on, a word with kept answers shows a faint dotted underline and the tooltip `Har sparade svar för en lucka` (copy to `ui-copy-reviewer`). With the tool off it looks like plain text (Q2 iii).
05. Kept answers live only in the workspace document. Print, PDF, QTI and every other export show the word as plain text (Q2 iv).
06. With the tool on, Enter or Space on a selected gap opens its popover. With the tool off, a gap click opens its popover (Q3).
07. The second click of a double click does nothing, so a double click never makes a gap and then reverts it (Q4).
08. The gap tool switch is the only gap control. The toolbar Lucka button and the floating Gör till lucka glyph are removed. With the tool on, Enter on a non-empty keyboard selection makes it a gap, so making a gap stays possible from the keyboard. This reverses the user's 40-04-09 Q5, Q12 and Q13 (Q5).
09. The Tom lucka command inserts an empty gap at the caret, to fill in afterwards (U4, replacing Q6). With a selection it inserts at the selection's end and deletes no text. It works with the gap tool on or off, and its popover opens at once. The toolbar emits `insertEmptyGap` and the body editor runs `insertEmptyGapAtCursor()` in `useExamWorkspaceMakeGap.ts`; its disabled reasons reuse `gapDisabledReason`. The glyph is drawn and wired by TASK-SKRIPT-40-04-17 (unit 5, huleedu-integrated 0.1.33); this task adds no button (L3).
10. An empty gap stays while its question is being edited, including clicks into it and opening and closing its popover (U4, replacing Q7). An empty gap is a Lucktext gap with no accepted answer in a question that has an answer key, or a dropdown gap with no correct option (Q9). When the teacher leaves the question (selects another question, closes the editor, or leaves the workspace route), every empty gap in it is removed silently as one undo step, with no toast. It never runs on page unload. Leaving a question is not itself an undo step, so the removal is its own single step; that is the faithful form of the user's "same undo step as the close" (U4, L3). A question without an answer key loses nothing.
11. The document may hold an empty gap: the step store and the Mina filer file accept it (L2). Export and print refuse a document with an empty gap on the server, and the export drawer shows a blocker that names the question by its list label and whose jump opens it (U4).

Scope split (orchestrator 2026-10-19): a separate Mac toolbar session owns the toolbar layout and the glyphs' look. That session also owns the switch glyph (Q8 text-select, look per TASK-SKRIPT-40-04-11). This task keeps the switch's current glyph, and removes Lucka and the floating glyph as behaviour.

### Document format (new; no reader for the old form)

- `NativeTextSegment` (`native_exam_body.py`) gains `kept_gap_id: str | None`, matching `GAP_ID_PATTERN`, null on ordinary text. It is not a mark: `marks` keeps the five formatting names, so the print, QTI and DigiExam code that reads `marks` is unchanged. Two neighbouring runs merge only when their marks and `kept_gap_id` are equal.
- `NativeExamItem` (`native_exam_item.py`) gains `kept_gaps: tuple[NativeGap, ...]` with the same `NativeGap` shape. Invariants: every kept gap id appears as `kept_gap_id` on at least one text run of the item's body, and every `kept_gap_id` in the body names one kept gap. Kept gap ids are unique, and differ from the item's `gaps` and chips. Only gap_fill and inline_choice items carry kept gaps, and each kept gap follows its kind's gap shape rules. Kept gaps are left out of the answer-key invariants and `body_gaps`, so they never count as gaps of the question.
- The SPA carries the same fields through the regenerated OpenAPI types. The TipTap editor maps `kept_gap_id` to a mark `examKeptGap` with a `gapId` attribute; the mark is not inclusive, so typing at the word's edges does not join the link. Removing the last run that carries an id drops its kept record, the same way `withBody` drops the record of a removed chip.
- A tool click on any part of a marked word restores the whole contiguous run that carries that id. If editing has split the id across separate runs, the clicked run is restored and the other runs lose the mark.

Non-goals: the toolbar layout and glyph look (the Mac toolbar session); toolbar Ångra, Gör om and autosave (TASK-SKRIPT-40-04-14); printing kept answers anywhere.
