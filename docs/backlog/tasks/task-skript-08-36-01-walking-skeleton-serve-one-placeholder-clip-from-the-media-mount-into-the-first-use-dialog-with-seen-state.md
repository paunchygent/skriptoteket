## Implementation Contract

Deliver the end-to-end vertical for one placeholder clip on Hemma dev.

- Backend: a `MEDIA_ROOT` setting (container default `/var/lib/skriptoteket/media`, host-dev default under `/tmp/skriptoteket/`) mounted at `/static/media` with Starlette `StaticFiles(check_dir=False)` so the app boots without the directory; range requests come from Starlette's file responses. `compose.hemma-dev.yaml` and `compose.prod.yaml` bind-mount the host directory read-only.
- Profile: a nullable JSON list column `classroom_planner_tutorial_seen_sections` on the user profile with an Alembic migration, exposed on the profile response and accepted by `PATCH /api/v1/profile/classroom-planner-settings` as `tutorial_seen_sections: list[str] | None` with replace semantics (the client sends the union). The endpoint's at-least-one-field validator counts the new field. The generated OpenAPI types are regenerated by the backend unit.
- Frontend: a zod manifest schema and one cached fetch per app load; a seen-state composable (guest key `skriptoteket:classroom-planner:tutorial-seen-sections:v1`, signed-in profile field); `TutorialClipDialog.vue` (centered, 16:9, `<video preload=none>` with poster, play control, other clips of the section, Swedish copy, close marks seen); thumbnails inside `HelpTopicPlanner.vue` per section; a first-use gate mounted on both planner hosts that watches the help context and fires only when the manifest and seen-state are loaded, the viewport matches `(min-width: 1024px)`, the authenticated guest-upgrade gate is `allowed`, and no planner dialog or the Hjälp panel is open.
- Dev proof data: a placeholder clip, poster and manifest hand-placed in `/home/paunchygent/apps/skriptoteket-media/dev/klassrumskartan/` until HuleFilm's publish step replaces them.
- Clip manifest at `/static/media/klassrumskartan/clips.json`: `schema_version` 1, `app` `classroom.group-seating-studio`, and `clips[]` with `id`, `section` (exactly `planner_overview`, `planner_seating`, `planner_grouping` or `planner_rules`), `order`, `title`, `duration_seconds`, `video` and `poster` as paths relative to the manifest. A missing manifest means no pop-up and no thumbnails; a missing video shows the poster with a Swedish load-error line while the written help stays.
- Media directory on Hemma at `/home/paunchygent/apps/skriptoteket-media/<dev|prod>/`, bind-mounted read-only at `/var/lib/skriptoteket/media` in the web container by `compose.hemma-dev.yaml` and `compose.prod.yaml`, served by the existing static mount at `/static/media`. The production compose change is inert until `hemma-deploy`, which needs its own authority.

## Core Vertical And Performance

Core vertical: manifest on the media directory, served by the static mount, read by the frontend, opening the dialog once per section, seen-state persisted for guest and signed-in, replay from Hjälp. Performance: one manifest fetch per app load, no video bytes until the user presses play, no layout shift in the help panel when thumbnails load.
